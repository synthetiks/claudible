## TL;DR — the live-session visibility saga, resolved

The recurring "MK can't see my live session" problem was **never one bug**. Its true root cause across all ten days was **invisible build drift**: the app runs from a git clone that had no update mechanism, so one collaborator ran six-week-old code while the other shipped fix after fix — every test compared new-code against old-code and "nothing changed." That is now closed three ways: an in-app **Update & restart** button, a **build-skew badge** that shows each side's commit on the live row, and the timing journal logging its own build at boot. The presence pipeline itself is now coherent at HEAD (per-workspace beacon chains, worktree-free presence plumbing, an optional sub-second relay, a 10s poll as subordinate fallback) with all cross-file constants verified consistent. **Both collaborators must be on `dc0892d` and restarted for any of it to matter** — which, as of this report, is finally true on both machines.

## Era-by-era history

### Era 1: The WSL2 Voice Cockpit Becomes a Multiplayer Terminal (2026-06-16 – 2026-06-20, commits 1–70, e22bd1d..0905725)

- **Narrative**: Claudible begins as a tightly-scoped "voice cockpit" for Claude Code on Windows+WSL2: `main.js` spawns `wsl.exe -e bash -lc "..."` into a `node-pty`/xterm.js terminal, `wsl/session.sh` bootstraps hooks/statusline into a private `~/.claudible/session` dir, and local Whisper/Kokoro services provide push-to-talk STT and spoken TTS with no cloud calls (`docs/ARCHITECTURE.md` at e22bd1d lays out the "three planes": input/output/meter, bridged via files on the Windows side to dodge the flaky 9P `\\wsl.localhost` boundary). Within 24 hours (c98f122) this pivots hard into the app's defining feature: self-hosted **live terminal sharing** — a loopback HTTP+WS `share/server.js`, a cloudflared quick-tunnel for the invite link, guest approval gating, and a mirrored guest browser UI. The rest of the era is a rapid sequence of deepening that multiplayer model: "Session = Workspace = Directory" (60fe5c2) turns each conversation into a directory-scoped workspace (legacy/local/private-GitHub-repo), Stage 2-4 sharing (f8e9e8b) lets a granted teammate browse a whole library of workspaces and become a real GitHub collaborator, `7766fbe` builds a full session-sync engine that copies Claude transcripts between collaborators over an orphan git branch (with an explicit trust boundary: transcripts synced in from someone else are marked "foreign" and resumed with approvals *on*, never under `--dangerously-skip-permissions`), and `2769096` replaces the single foreground pty with a tab-aware `Map` of concurrent ptys plus a workflow/swarm "Agents" view. A second contributor ("MK") joins mid-era and drives most of the sharing/voice/tabs work forward. The voice feature itself goes through a real architectural failure and recovery inside this same era: WebRTC voice rooms are added (959da9f), hit five rounds of NAT/STUN/TURN/CSP failures and a subtle Electron IPC `DataCloneError` that silently dropped the host's signaling (a313c70, "THE bug"), and are ultimately abandoned in favor of relaying raw PCM audio frames through the same proven share-server pipe used for the terminal (c4b9c4f) — a "drop P2P, trust the thing that already works" decision. By commit 70 the app also has a Diff Review panel (revert Claude's changes per hunk/file), HTML session-replay export, and a workspace/session model solid enough that a dedicated adversarial-review pass (bd5be13) found and fixed 7 real defects in one sitting — establishing the "adversarial multi-agent review" QA pattern that recurs for the rest of the project's history (visible at HEAD in dc0892d's "11-agent master audit").

### Era 4: The Rename Root-Cause Hunt and the Session-History Engine (2026-06-29 – 2026-07-02, commits 211–280, `59832a2`..`07d7801`)

- **Narrative**

This era opens with a textbook debugging spiral and closes with a full feature built from a pure core outward. The first act is the "rename saga": seven consecutive commits (`59832a2` → `bbad946`) chasing a single user report — "I renamed a session, it said renamed, the name didn't stick." Each commit fixed a *real* problem it found (no confirm/cancel affordance, a shared-title race, xterm stealing focus) and each time the bug persisted, because none of them was the actual cause. The saga ends with a genuinely subtle root cause: `settingsInitial` crosses Electron's `contextBridge` frozen, so a shallow `Object.assign` merge in `loadPrefs()` left `sessionTitles` pointing at a frozen object — every `titles[id] = name` write silently no-op'd. The fix (deep-clone via JSON round-trip) is a good example of "diagnose before patching" paying off only after several rounds of not doing that; the commit trail itself is left in the repo as a case study, with diagnostic `console.log`/toast breadcrumbs added and then deliberately removed once the layer was confirmed.

The second and larger act is the ground-up build of **Session History**: an append-only, pure, IO-free event-log core (`lib/history.js`) with identity/attribution (`lib/identity.js`), atomic disk persistence (`lib/historyStore.js`), flag-gated IPC wiring, a renderer activity feed, and — via the already-tested `lib/checkpoint.js` — git-backed per-prompt snapshot/restore wired into a one-click Revert with an "Undo last revert" safety net. It shipped in careful phases (1 through 7, each individually tested and left inert/off by default until the next phase consumed it), interleaved with real bugs found along the way (timestamp truncation via `| 0`, wrong-workspace writes during a tab switch, attribution crediting the host instead of the co-driving guest, non-atomic restore on a failed checkout). In parallel, the live-share subsystem got a security and resilience pass: unique guest names under concurrent joins, sticky divergence flags, a presence-file JSON validator, synchronous resume-token revocation on kick, and two rounds of XSS hardening (host-controlled peer strings going through `innerHTML`). The era closes with the model itself gaining situational awareness — `af4ad339` injects live machine/user/session identity into every turn via a `UserPromptSubmit` hook, adversarially reviewed and patched for a real prompt-injection vector (a guest naming themselves to break out of the trusted context block) — plus a long tail of small, well-isolated correctness fixes (diff byte-vs-char bounding, voice fetch timeouts, presence pinned to the advertised not active workspace, mic-blocked surfacing in restrictive webviews).

### Conflicts §4. The recurring live-visibility saga — current end-to-end design

As of HEAD, "peer sees a live/new session" works through three cooperating layers, confirmed present and mutually consistent in `main.js`, `wsl/sessions-sync.sh`, `wsl/sessions-sync-tool.js`, and `lib/presenceRelay.js`:
1. **Per-workspace beacon chains** (`main.js:1550-1660`) independently probe each synced repo's branch head via bare `ls-remote` every 1.5s (8s when the window is hidden), with exponential backoff per dead remote so one deleted/unreachable repo can't stall others.
2. **Worktree-free presence plumbing** (`_presQ` lane) writes/reads the `live/` subtree directly against the git object graph (no worktree, no index, no lock contention with transcript syncs), with a two-phase advertise (an inert "starting" stamp immediately, replaced by the full handle once the tunnel is up).
3. **Optional realtime relay** (`relay/worker.js`, a Cloudflare Worker) fans out presence frames over WebSocket for sub-second visibility when deployed; it's strictly a preview layer — git presence remains authoritative and always reconciles over it (`reconcilePeerLists` prefers strictly-newer per-login entries), and it no-ops completely when `RELAY_URL` is unset.
4. A 10s renderer poll remains as the final fallback, now demonstrably subordinate to the above (not the primary path it used to be).

No remnants of the old designs interfere: the "front-of-queue" primitive is unused, the fetch-based probe variant was fully rolled back to `ls-remote`, and constants are cross-file consistent. The only real gap is documentation: the release-contract docs (`FINISH-LINE.md`, `TWO-MACHINE-TEST.md`) still encode the *pre-rewrite* latency numbers and have not been re-run/updated against this final design.
